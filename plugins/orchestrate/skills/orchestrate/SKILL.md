---
name: orchestrate
description: Load this whenever you are about to spawn a sub-agent (Agent, spawn_agent or task tool), whether or not the user asked for delegation. It sets the effort every spawn names, says when a helper is one-shot and when it is retained, and who picks the model; it never asks you to delegate. Also the delegation command itself — "/orchestrate <model> <effort> <task>", or "use a <model> subagent at <effort> to …" — which hands one task to one sub-agent in one continuous thread while you coordinate and verify evidence.
---
## Every spawn

This part applies whenever you delegate, invoked or not. Whether to delegate at all stays your call; working directly is fine.

- **Effort.** Choose it with the rubric below. A level the user named wins. In Claude Code, pass it on every spawn; Codex and OpenCode follow their own lines below. The Claude Code spawn hook gives a `general-purpose` or shim spawn that names no effort `high`, or your own level when that is lower, so an `xhigh` session no longer hands `xhigh` to every helper. It does not touch named roles (Explore, web-fetch and other built-ins or custom agents), which otherwise inherit your level: pass `effort` on those too, unless the role's own definition sets one you mean to keep.
- **Lifetime.** Prefer a one-shot helper: a self-contained brief, one result back, done. A named helper you keep messaging is for one continuous task, the retained owner below, and you stop messaging it when that task ends. It is not a standing assistant: every message to a live helper re-reads its whole context, so a new question goes to a new one-shot helper with a tight brief.
- **Model.** Only the user chooses one, as below.

## The invocation

Parse the invocation: the first two words after /orchestrate are {model} and {effort_level} when they are a model name and an effort level; anything after that is {task}. If the model is absent, none is named and the sub-agent inherits yours. If the effort is absent, you choose it, as below. {rounds} defaults to 3 and {done} to "the deliverable is complete with acceptance evidence" — the task text may override both ("stop after 5 rounds", "until the numbers reconcile").

Only the user chooses a model. Leave it out unless they named one, and never pick one yourself: the sub-agent then runs on your model.

Effort is yours, because you hold the user's actual words. A level the user named wins. Otherwise judge the request and the work, whatever words they used; with no level chosen, a Claude Code sub-agent gets the hook's default above and a Codex or OpenCode one runs at its native default:
- `low`: well-understood or mechanical work, or they asked for a quick pass.
- `medium` or `high`: everything in between, in proportion.
- `xhigh`: ambiguous investigation or design, work with many interacting parts, or any request for unusual care ("use lots of tokens", "iterate until you're proud", "don't miss anything"). It costs more for the sub-agent's whole run, so use it on that evidence, not by habit.
- `max`: only when the user asks for it.

- Claude Code: leave the model out of the Agent call unless the user named it, pass `effort` when you chose one, and use the plain `general-purpose` role. The plugin's spawn hook drops any model the call names that the user did not name in their latest message. It keeps an effort the call asks for (an `effort` field or a shim type); with none, it uses the level named in the user's latest `/orchestrate` or "use a … subagent at …" invocation, else the default above. It caps both, and always sends effort as the call's `effort` field. An invocation above chooses both (one naming no model, such as `/orchestrate have fable review it`, takes it from its task text as below); outside one, a message that names a model family ("I'd like fable to take a look", "compare Opus and Sonnet") keeps that family when you pass it as the call's `model`, so pass it only when the user is asking for it, not for "not opus" or "write a haiku". There is no workflow fallback pair. A named role (anything but `general-purpose` or a `worker-<level>` shim) is never rewritten: it keeps its installed model unless you name one in the call.
- Codex: name a model only when the user named one, and set an effort only when one was deliberately selected; omit any field you intend the runtime to resolve. Never Astra above `high` or Sol above `xhigh`. A named agent role keeps the model and effort set in its own definition.

Use the selected model and effort when present; omit a field left to native resolution. Use one sub-agent to do all of the work on {task} in one continuous thread. The retained owner implements, runs the checks and repairs failures. You coordinate and verify evidence; you do not repeat the substantive work yourself.

Verification is whatever the deliverable demands, decided from {task} before the first dispatch: a product or UI → run it and browser-test, screenshot in hand; code → build, run the tests, exercise the change; analytics → re-run the queries, validate the data and the math, cross-check numbers and insights against the source; documents or research → check claims against their sources. If {task} names the check or its verification owner, honor that explicit user override. Otherwise the retained owner performs verification and reports the exact artifact, command, result and limitations. Say in one line which check you chose and who owns it. Owner testing is not independent review; when independent review is required, use a separate reviewer with fresh context.

Each round: resume the same retained owner with the original brief, evidence-backed findings and the latest artifact (screenshot, output, query result). The owner builds, tests and repairs within that session, then reports acceptance evidence and unresolved findings briefly. A stage change does not justify a new worker or repeating checks on an unchanged artifact. Stop after {rounds} corrective rounds, or when {done}; a stop with unmet acceptance criteria is incomplete, never successful verification.

A native concurrency/capacity rejection ends the dispatch burst. Record unstarted work and its original deadline in the normal summary/checkpoint; retain accepted worker handles. Never change names, models, effort or owners to bypass the limit. A new native completion/close notification for an accepted handle, or a native limit-change notice, permits one admission attempt; it does not prove a free slot. Rejection stops the burst until another such change; duplicate notices permit no extra attempt. Preserve failed-worker evidence and make one owned recovery decision; send test repairs to the same live owner. Completion is not acceptance: keep artifact checks and required independent review.

Dispatch on this runtime:
- Claude Code: Agent tool, subagent_type "bootstrap-orchestrate:worker-{effort_level}" with `effort: "{effort_level}"` (or `general-purpose` and no `effort` when no level was chosen, which the hook then fills with its default), model = the family alias for {model} (fable, opus, sonnet, haiku — a specific version cannot be named; say so if one was asked for; omitted when left out), a fixed name; every later round is SendMessage to that name. Always pass `effort` when an effort was chosen: current Claude Code does not apply a shim's `effort` frontmatter, so the shim type alone runs at the default level. The shim name only labels the level.
- Codex: spawn_agent with model {model}, reasoning_effort {effort_level}, and an explicit fresh-context control from the exposed tool schema: `fork_turns: "none"` (v2) or `fork_context: false` (v1) for a new bounded worker. Do not omit the control. Supply a self-contained brief with authority, scope, relevant paths, acceptance criteria and evidence; every later round goes to that agent id, including build, test and repair. Do not spawn a replacement at a stage boundary.
  Workers never inherit this conversation: the hook denies `fork_context: true` and any `fork_turns` other than `"none"`. A worker that shares your context cannot check your work, and a fork skips the model and effort you named. v1 silently ignores `fork_turns`; v2 rejects `fork_context`. See [Codex context guard](references/codex-context.md) for coverage and activation checks.
- OpenCode: task tool with agent "worker-{effort_level}" when that agent exists; if it does not, dispatch the default sub-agent and say in one line that effort could not be set. The sub-agent runs the parent's model either way.
